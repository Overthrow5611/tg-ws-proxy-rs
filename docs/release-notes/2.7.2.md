# v2.7.2

## Android

- Default arguments now use a 4 s WebSocket connect timeout, and the same 4 s
  while a DC is in failure cooldown (`--ws-connect-timeout 4
  --ws-fail-probe-timeout 4`). Before, one lost connect cut every dial for the
  next 30 s to the 2 s probe timeout; with `--pinned-upstream ws` there is no
  next tier to fail over to, so that only dropped clients sooner and kept the
  cooldown alive. 4 s also leaves room for a third SYN on a lossy path.
  Saved arguments are not changed on update; edit them in the app.
